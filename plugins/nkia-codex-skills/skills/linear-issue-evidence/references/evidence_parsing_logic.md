# AC·증빙 파싱과 갱신

[공통 계약](../../../references/issue-contract.md)의 저장·표시 규칙을 따른다.

1. `## 3. 완료 조건`과 기존 Acceptance Criteria·AC·DoD 제목을 인식한다.
2. 체크리스트의 AC ID, 결과 문구, 체크 상태, 다음 AC 전까지의 증빙 링크·대표 이미지를 하나의 항목으로 읽는다. 들여쓴 증빙 항목을 새 AC로 세지 않는다.
   - 증빙 불릿 아래의 짧은 실제 출력 코드 블록도 해당 AC 증빙으로 읽는다. 짧은 결과에 링크가 없다는 이유만으로 증빙 누락으로 판단하지 않는다. 장문 링크는 Linear document 내용을 연다.
   - `증빙 예정:`은 수집할 자료·확인 내용으로, `증빙:`은 실제 자료로 구분한다. 예정 문구를 완료 증빙으로 세지 않는다.
3. 정식 AC ID가 없으면 기존 문구·순서와 inline 자료를 사용한다. 모호한 매칭은 임의로 수정하지 않는다.
4. 원본 저장 후 최신 본문을 다시 읽고 대상 AC의 체크와 증빙 요약만 갱신한다. 전체 문서 문자열 치환으로 다른 AC의 같은 링크를 바꾸지 않는다.
   - 확인된 자료에 대응하는 `증빙 예정:` 불릿을 `증빙: 실제 링크·결과`로 교체한다. 이미 실제 증빙이면 같은 불릿을 갱신한다. 예정 불릿이 없는 기존 AC에는 하위 불릿을 추가한다. 다른 예정 자료가 남으면 보존하고 AC를 체크하지 않는다.
5. 재검증 시 기존 증빙·실패 이력을 검증 댓글에 보존하고 대상 AC의 최신 요약을 교체한다. 보존 실패 시 덮어쓰지 않는다.
6. 기존 `→ 결과물:`, 코드 블록, inline 이미지는 읽을 수 있어야 한다. 사용자가 전환을 요청하지 않은 기존 증빙은 일괄 삭제하지 않는다.
7. 재조회로 실제 자료와 AC 연결, 체크, 다른 본문의 보존을 확인한다. 불확실하면 완료로 보고하지 않는다.

새 증빙 예:

```markdown
- [x] **AC-01** 필터 변경 시 해당 대상의 결과가 표시된다.
  - 증빙: [검증 리포트](실제-URL) · 필터 전환 테스트 8/8 PASS
```
