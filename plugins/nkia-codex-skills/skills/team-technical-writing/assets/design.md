# [제품·기능명] 주제 설계

- **핵심:** 해결할 문제와 제안하거나 채택한 설계.

- **상태:** 현재 구현 / 제안 / 검토 중에서 사실에 맞는 상태.
- **대상:** 주요 독자와 적용 범위. 필요하면 담당자·기준일·버전을 함께 표시한다.

## 설계와 선택 이유

- **문제:** 사용자가 겪거나 시스템에서 해결해야 하는 구체적 문제.
- **설계:** 무엇을 어떻게 처리하는가.
- **이유:** 이 방식을 고른 이유와 근거. 실제 검토한 대안이 있을 때만 비교한다.

## 동작과 계약

순서가 중요하면 입력 → 처리 → 출력 순서로 설명한다.

- **입력·출력:** 필드의 의미, 단위와 제약. 여러 필드는 표로 비교한다.
- **예외:** 실패 조건과 동작. 정상 동작의 핵심 예시를 필요할 때 추가한다.

## 제약과 미결정 사항

- **제약:** 적용되지 않는 범위와 주의할 조건.
- **확인 필요:** 아직 정하지 못한 항목과 결정에 필요한 정보.
- **근거:** 코드·이슈·평가 자료의 실제 링크.
