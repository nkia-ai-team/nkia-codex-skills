# 설명 밀도와 형식 예시

가상의 예시다. 실제 문서의 상태·수치·정책으로 재사용하지 않는다.

## 불릿으로 동작과 이유 분리

Before: “state가 overwrite라 최초 prepend만 하면 소실. 매 턴 entry에서 주입.”

After:

- **처리:** 매 대화 턴 시작 시 참고 정보를 메시지 앞에 추가한다.
- **이유:** 메시지 상태가 덮어써져, 처음에만 추가하면 다음 턴부터 사라진다.

짧게 줄이는 대신 필요한 이유를 풀어 쓰고 훑어보기 쉽게 나눈다.

## 측정 결과와 판정 구분

Before: “평균 0.4초, 최대 0.6초. 응답 시간 0.5초 미만 기준 PASS.”

After:

- **관측:** 평균 0.4초, 최대 0.6초였다.
- **판단:** 평균 기준이면 충족하지만 모든 요청 기준이면 충족하지 못한다. 어떤 통계량으로 판정하는지 확인해야 한다.

수치의 뜻을 보존하고 모호한 판정을 새 정책으로 확정하지 않는다.

## 짧은 변경은 짧게 유지

입력: “설정 화면의 저장 버튼 문구를 ‘확인’에서 ‘저장’으로 변경했다. 기능 변경은 없다. 변경 기록으로 써줘.”

출력:

# 설정 화면 저장 버튼 문구 변경

- **변경:** 버튼 문구를 ‘확인’에서 ‘저장’으로 바꿨다.
- **영향:** 기능 변경은 없다.

원인·테스트·후속 작업을 추측해서 채우거나 빈 절을 추가하지 않는다.

## 좋은 설명은 유지

“특정 동작 자체에는 보상하지 않는다. 그렇지 않으면 해당 동작만 반복해 보상을 얻을 수 있다.”

결정과 이유가 이미 연결되어 있다. 별도의 불릿·표·마지막 요약을 강제하지 않는다.

## 결과 보고는 작업 회고를 줄이기

Before: “검토 과정에서 다음 개선 지점을 정리했다. 배경·세부 설명 사이에서 현재 상태와 결론을 찾아야 했다. 문서 작성 규칙을 개정하고 두 저장소에 스킬을 추가했다.”

After:

- **문제:** 긴 배경 설명에 핵심이 묻힘
- **완료:** 문서 작성 규칙 개정, 두 저장소에 작성 스킬 추가

내용 없는 도입을 삭제하고 문제와 결과를 직접 제시한다. 같은 완료 내용을 개요·진행 과정·결과물에서 반복하지 않는다. 실제 비교·검증을 요구받으면 해당 근거는 남긴다.
