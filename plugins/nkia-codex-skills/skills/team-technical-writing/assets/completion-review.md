# [제품·기능명] 개선 방법과 검증 결과

- **목적:** 해결할 문제와 이번 리뷰에서 확인할 범위.
- **상태:** 제안·구현·배포·검증 상태를 구분. 짧은 결과 요약은 필요할 때만 추가.

## 기존 문제

- **기존 방식:** 어떤 입력과 기준으로 동작했는가.
- **문제·영향:** 구체적인 실패 사례와 개선 필요성.

## 개선 방법과 정책

- **접근:** 무엇을 왜 변경했는가. 제안과 실제 적용을 구분.
- **입력과 관계:** 자료의 출처, 대상 간 연결 생성 조건, 연결의 의미와 사용 시점. 관계가 직접·간접인지, 방향을 사용하는지 등 판단에 필요한 항목을 설명.
- **알고리즘:** 입력 → 전처리·정규화 → 관계·점수 계산 → 그룹·결과 결정. 이름과 설정값 나열로 설명을 끝내지 않음.
- **정책:** 결합·분리·갱신·종료 조건, 시간 경계와 예외. 해당 기능에 필요한 정책만 선택.
- **사례:** 대표 입력이 정책과 알고리즘을 거쳐 어떤 결과가 되는지 연결. 자료가 있으면 기존 방식과 비교.

전체 흐름과 필요한 부분 흐름을 도표로 설명한다. 연결선에 관계·조건을 표시하고 실제 삽입 크기에서 읽을 수 있는지 확인한다.

## 결과와 검증

| 확인할 문제·기준 | 기존 결과 | 개선 결과 | 검증 조건·근거 |
| --- | --- | --- | --- |
| 실제 평가한 항목 | 확인된 값 | 확인된 값 | 데이터·환경·실행 근거 |

저장 데이터 평가와 실제 환경 검증, 미검증 범위를 구분한다.

## 한계와 후속 작업

- **남은 문제:** 미해결·미검증 항목과 영향.
- **다음 작업:** 필요한 검증·조치, 확인된 담당자·일정.
- **상세 자료:** 구현 경로·원시 결과·전체 실행 기록의 확인된 링크.
