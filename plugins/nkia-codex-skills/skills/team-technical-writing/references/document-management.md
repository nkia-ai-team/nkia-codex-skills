# 제목·위치·갱신

팀 기준 출처: [AI 1 team 문서 관리 규칙](https://nkia-ai.atlassian.net/wiki/spaces/NKIAAI/pages/1835010), 확인 버전 5, 2026-09-10. 아래는 해당 규칙과 합의한 제목 작성 방식을 스킬에 적용한 기준이다. 문서 작업에 필요한 내용은 이 파일에 포함되어 있다. 연결이 없어도 로컬 초안은 작성할 수 있으며, 최신 팀 규칙과 다를 가능성은 알린다.

## 제목

- 대상과 목적을 제목만으로 알 수 있게 쓴다. 프로젝트 문서는 `[제품·기능명] 구체적인 주제와 문서 목적`을 기본으로 한다.
- 일반 운영 문서는 `개인 개발 VM 접속 가이드`처럼 대상이 분명하면 접두어를 생략한다.
- 제품·기능명은 기존 대표 표기를 따른다. `Chat AI`, `CHAT AI`, `ChatAI`를 임의로 섞지 않는다.
- 실험·장애 기록의 날짜와 적용 버전은 구분에 필요할 때 붙인다. 단순 편집일을 사건일로 쓰지 않는다.
- 지속 갱신 문서에 `최종`, `최신`, `최종수정`을 붙이지 않는다. 적용 버전과 기준일은 본문에서 관리한다.
- 기존 제목 수정은 요청 범위와 탐색상 이득을 고려한다. 문장 수정만 요청받았으면 자동으로 이름을 바꾸지 않는다.

예: `테스트 결과` → `[TSShort] API 응답 시간 평가 — 2025-12-02`. 이 날짜는 해당 예시의 측정일이며 새 문서에 재사용하지 않는다.

## 위치

1. 사용자가 지정한 위치가 있으면 따른다. 없으면 관련 프로젝트·기능의 기존 상위 페이지와 유사 문서를 확인한다.
2. 수정 요청은 기존 페이지를 갱신한다. 새 페이지가 필요할 때만 아래 분류에 맞춰 배치한다.
3. 실제 페이지 ID와 계층을 확인한 뒤 사용한다. 아래 이름은 논리적 분류이며 고정 경로나 자동 폴더 생성 지시가 아니다.

| 분류 | 대상 |
| --- | --- |
| Projects / 프로젝트·기능 | 진행 중인 설계, 개발 계획, 평가 결과 |
| Areas / 제품·책임영역 | 계속 사용하는 API 명세, 운영 절차, 온보딩 안내 |
| Resources / 주제 | 외부 API 문서, 논문, 학습 자료 |
| Archives / 기존 분류 | 종료된 활동 기록, 대체된 문서 |

- 개발 중 API 설계와 운영 중 API 기준 명세를 쓰임새로 구분한다. 프로젝트 종료만으로 현재 사용 중인 문서를 보관 처리하지 않는다.
- 개요에서 세부 자료로 연결하고 기준 문서는 하나만 유지한다. 로컬 파일명만 적지 말고 공유 가능한 링크를 사용한다.
- 기능·제품과 문서 유형 라벨은 기존 표기를 재사용한다. 상태 라벨은 필요한 경우에 추가한다.
- 로컬 Markdown은 저장소의 문서 경로·파일명 관례를 따른다. Confluence 분류를 로컬 폴더로 강제하지 않는다.
- 게시 위치를 확인할 수 없으면 제안 위치를 표시한 초안을 제공한다. 존재하지 않는 페이지 ID나 경로를 만들지 않는다.

## 게시·갱신

- 게시 요청이 있을 때 사용 가능한 Confluence 도구를 확인한다. 이 스킬은 특정 플러그인이나 명령이 설치되어 있다고 가정하지 않는다.
- 기존 페이지는 쓰기 직전에 다시 읽어 최신 내용과 변경 범위를 확인한다. 도구가 지원하면 버전 충돌 방지를 사용한다. 충돌 시 최신 내용을 다시 읽고 요청한 변경을 재적용한다.
- 제목·상위 페이지·권한·담당자 등 요청과 무관한 설정은 보존한다. 게시에 필요한 대상 정보가 없으면 초안을 완성한 뒤 해당 정보만 질문한다.
- 작성자가 최초 담당자를 맡고 지속 관리 문서에는 담당자를 표시한다. 실제 사람을 확인할 수 없으면 임의로 배정하지 않는다.
- 기능·API·설정·절차 변경과 함께 관련 기준 문서를 갱신한다. 담당자·기준일·상태는 짧게, 상세 변경 이력은 페이지 이력이나 하단에 둔다.
- 승인된 문서 이동·대체 시 이전 안내와 개요 링크를 점검한다. 이전 문서에는 대체됨과 최신 링크를 표시한다.
- 게시 후 본문을 다시 읽어 제목 계층·불릿·표·코드·링크와 누락 여부를 확인한다. 화면 확인이 가능하면 실제 표시도 확인한다. 구조만 읽었으면 화면까지 검증했다고 보고하지 않는다.
- 담당자의 월 1회 기준일·담당자·링크·대체 여부 점검은 팀 운영 규칙이다. 이 스킬 사용만으로 반복 자동화를 만들지 않는다.

외부 도구 오류가 나면 성공했다고 보고하지 않는다. 생성 요청의 결과가 불명확하면 먼저 동일 페이지가 생겼는지 확인해 중복 생성을 피한다. 로컬 결과와 남은 조치를 전달한다.
